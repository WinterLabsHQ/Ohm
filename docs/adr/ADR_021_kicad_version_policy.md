# ADR-021 — KiCad version policy: one format out, provenance for what comes back

Date: 2026-08-26 · Status: accepted

## Motivation

Ohm targets KiCad, which is a moving target. Two things about that relationship
were load-bearing and unrecorded, and both produced defects that reached users.

**The format Ohm writes** had a policy — write KiCad 7, never bump — that existed
only in two commit messages. Nothing linked it to the four constants that
implement it, and nothing said what followed from it.

**The libraries Ohm references** had no policy at all. A `package = "Lib:Footprint"`
reference emits a pad-*less* stub: the geometry comes from the user's installed
library at layout time, and only the pad id travels, in the netlist. So the
netlist is correct only if the pad id Ohm names still exists in the library on
that machine. KiCad 10 normalised shield and shell pads to `"SH"` across **163**
footprints (`0`, `S1`, `6`, `5`, `11`, `9` all became `SH`). Three of Ohm's own
standard-library parts named the old ids, so on KiCad 10 their shields bound to
pads that do not exist — an unconnected shield, passing every check Ohm had.

S003 proves a pin→pad map is TOTAL. Nothing proved the pads it names EXIST. That
is the same shape of gap ADR-014 closed for symbols, one layer down.

## Decision

### 1. One emitted format, forever

Ohm emits the **KiCad 7** file format for every `--target-kicad`, and the four
version stamps are never bumped:

| Artifact | Constant | Value | Where |
|---|---|---|---|
| `.kicad_sch` | `_SCH_VERSION` | `20230121` | `ohm/emit_kicad.py` |
| `.kicad_pcb` | `_PCB_VERSION` | `20221018` | `ohm/emit_kicad.py` |
| `.kicad_mod` | `_FP_VERSION` | `20221018` | `ohm/pkggen/footprint.py` |
| `.kicad_sym` | `_SYM_VERSION` | `20220914` | `ohm/pkggen/symbol.py` |

KiCad reads **forward**, and that is the direction it guarantees. A newer stamp
would buy nothing and cost every older KiCad the ability to open the file.

Two consequences, both previously unstated:

- **`--target-kicad` names the KiCad you are targeting, not a serialisation.**
  It accepts `7|8|9|10`. Refusing 10 told users running the version the README
  certifies that their KiCad was unsupported.
- **Every reader Ohm owns must be structural, not layout-anchored.** Readers face
  the other way — at files the user's KiCad wrote. A line-anchored parser has
  been broken twice by nothing more than a pretty-printer change (KiCad 9's
  `(class "Default")`, KiCad 10 splitting nets across lines), and once by a
  semantic one: KiCad 10 dropped the top-level net table and now names nets
  inline (`(net "R1_P2")` where 7–9 wrote `(net 3 "R1_P2")`), which made
  `ohm signoff` report V001 on every pad of any board KiCad 10 had saved.

### 2. Footprint pad provenance — ADR-014's pattern, one layer down

ADR-014 solved "is this pin→pad map CORRECT?" for symbols with: acquire at author
time, freeze, check against the frozen copy, and re-verify against the real
library out of band. The footprint side now works the same way.

- **`ohm/fpdata/pads.json.gz`** — the pad ids KiCad's own footprints carry, for
  every footprint in every supported major (15,473 footprints × KiCad 8/9/10,
  158 KB). Generated by `tools/gen_fpdata.py` from real installed libraries;
  byte-reproducible (sorted keys, `gzip mtime=0`), so a difference is a real
  library change and never churn.
- **S012** checks declared pads against that table at `ohm check` time —
  hermetically, because the table ships with Ohm rather than being read off the
  user's disk (N1).
- **`ohm verify-footprints`** is the author-time half that re-reads the *real*
  installed library and diffs, exactly as `ohm verify-pinouts` does for symbols.
  Impure by nature, therefore never on the parse→emit path.
- **CI regenerates the table** at every matrix version and fails if it differs
  from what is committed. The KiCad 10 rename reached users precisely because
  nothing noticed a library had changed.

### 3. What the table refuses to do

- **Unknown footprint → abstain.** Users reference their own and third-party
  libraries. Guessing about those is how a checker earns the right to be ignored.
- **Unknown major → abstain, never "clean".** KiCad 7 has no official container
  image, so the table has no KiCad 7 data. A KiCad 7 target is *unchecked*, and
  must be reported as such rather than silently passing.
- **Renames are derived old→new only.** Ten of the 163 footprints MERGE two
  shield pads into one `SH`; the reverse direction is genuinely ambiguous after a
  merge, so it is not offered.

## Consequences

- A whole class of silent defect — a pin bound to a pad that does not exist —
  becomes a diagnostic, for user designs and not merely for the three standard
  parts that happened to have tests.
- The supported KiCad range is now **measured**: `.github/workflows/ci.yml` runs
  the emit, library, read-back and plot gates against 8.0.9, 9.0.9 and 10.0.5 in
  the official containers, with `OHM_REQUIRE_KICAD=1` so a skipped KiCad test
  fails the run instead of quietly passing it.
- **KiCad 7 is the weak leg.** No container image exists below 8.0.4, so 7 is
  certified by hand or not at all, and carries no pad data. If that is not
  acceptable, the honest move is to raise the supported floor to 8 rather than
  keep claiming a version nothing exercises.
- The table is a maintenance obligation: a new KiCad major means a new dump and a
  reviewed diff. The CI job makes that obligation visible rather than optional.

## Alternatives rejected

- **Vendor the footprints themselves** (emit real geometry instead of stubs).
  The strongest guarantee — Ohm's board would be identical on every KiCad and
  depend on no library at all — but it means shipping KiCad's library data
  (CC-BY-SA 4.0 plus a design exception) inside a proprietary product, which is a
  licensing decision rather than an engineering one. Deferred, not dismissed.
- **Generate connectors in `pkggen`.** Not viable: connector land patterns are
  vendor-specific per part, not formula-driven the way IPC-7351 IC packages are.
  `pkggen` has no connector families and adding them needs per-part mechanical
  drawings, which is exactly the acquisition problem `pindata_iface` keeps out of
  the build path.
- **Detection only, with no vendored data.** `verify-footprints` alone would
  catch renames, but only where KiCad is installed and only when someone runs it
  — so it could not fire during an ordinary `ohm check`, which is where the
  defect needs to surface.
